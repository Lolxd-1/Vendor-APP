# T05: Orders screen, OrderCard, RejectSheet, StoreSwitch, setup banner
Wave: 4 · Deps: T04 · Risk: high · Model: opus

## Goal
The Orders tab in the new design (PLAN "Design plan" wireframe) with the action sequences of today's OrderCard kept
exactly (AC2), the Zomato late-order behavior (AC6), preset reject reasons (AC7), the Online/Offline switch with
confirmation (AC5) and the setup warning banner (AC12).

## Context
Today's `OrderCard.run()` is the ring-stopping contract: await REST → markLocal(id, action, prep) → pollNow(); on error
set the same failure text and re-enable. Keep that function's body semantics verbatim. Failure strings to keep:
'Accept failed — it may still have been accepted. Wait a few seconds before retrying.', 'Reject failed. Try again.',
'Could not mark ready. Try again.', 'Could not hand over. Try again.' (+ ` (${message})` when status ≠ null).

## Steps
1. OrdersScreen: own the 1 s `now` tick; LargeHeader title "Orders", subtitle row = shop name (or "Shop #id") on one line,
   then "Shop #<id>" footnote + connection StatusPill (Live green wifi / Connecting amber refresh-cw / No connection
   red wifi-off); right = StoreSwitch. Below: SetupChecklist banner (only when something is missing; "Fix" opens the
   Alerts page via onOpenAlerts), Segmented New/Preparing/Ready with counts (New `alert` when > 0). When New has
   orders show a blue info strip "Phone keeps ringing until you accept or reject" with bell-ring icon. FlatList of
   OrderCards; EmptyState per segment: New bell 'No new orders' / 'The phone will ring when one arrives.'; Preparing
   chef-hat 'Nothing being prepared'; Ready package-check 'No orders waiting for a rider'.
2. StoreSwitch: pill button showing dot + 'Online' (green) / 'Offline' (red) + RN Switch; tapping when online opens a
   Sheet "Go offline?" body "Customers can't order from you until you go online again. Orders already placed will
   still ring." with danger "Go offline" + ghost "Stay online"; going online calls setOnline(true) directly. When
   status.reason === 'schedule' show 'Closed by store timings' caption and tapping opens a Sheet explaining it with a
   "Open store timings" button (callback prop) instead of toggling. Busy → spinner; error → ToastAndroid.
3. OrderCard (memo) per phase, sections in order: header (PENDING = blue band, white text: bell-ring icon, 'New order',
   big tabular elapsed `elapsedLabel(creationTime)`; ACCEPTED = id + countdown pill amber/red 'mm:ss left' / 'Late by mm:ss'
   + thin progress bar; READY = id + green pill 'Ready mm:ss ago'); meta line '#<orderId>' + 'Placed <clockTime>';
   customer name + payment label + amount (headline, right); items list (qty in blueSoft rounded square, name, line price);
   instructions box (message-square-text icon) when orderDescription non-empty; rider block for ACCEPTED/READY: bike icon,
   name or 'Finding a rider', riderStatusLabel, Call button (Linking.openURL(`tel:${phone}`)) when phone; pickup code
   block: key-round icon, 'Pickup code', 4 digits large tabular with letter spacing.
   Actions: PENDING → prep stepper ('Ready in' label, minus/plus round buttons stepping through PREP_TIME_OPTIONS,
   value '<n> min'), primary l 'Accept order' (busy), ghost red 'Reject' → RejectSheet. ACCEPTED → primary l
   'Mark food ready' (variant danger + pulse + card red border when late). READY → success l 'Hand over to rider'
   disabled unless canHandOver, hint 'Unlocks when the rider reaches your shop.' with info icon. Success → ToastAndroid
   'Order accepted' / 'Order rejected' / 'Marked ready' / 'Handed over'.
4. RejectSheet: title 'Reject order?'; radio rows: 'Item out of stock', 'Kitchen is closing', 'Too many orders right
   now', 'Other reason' (shows TextInput); danger l 'Reject order' (disabled until a choice); validation via
   isValidRejectReason(reason, MIN_REJECT_REASON) → 'Reason must be at least 3 characters.'; calls onConfirm(reason.trim()).
5. SetupChecklist: compact amber banner: triangle-alert + 'Orders may be missed' + count of missing items + 'Fix' button.
