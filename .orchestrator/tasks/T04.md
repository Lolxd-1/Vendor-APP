# T04: App shell, bottom tab bar, back handling, Login redesign
Wave: 3 · Deps: T01 T03 · Risk: high · Model: opus

## Goal
`App.tsx` renders `MainShell` when logged in: 4-tab bottom bar (Orders badge = pending count), page stack
(timings, alerts) with Android back handling, board/setup subscriptions lifted from OrdersScreen, and the
pending-increase → Orders/New switch. Login gets the new look with identical logic.

## Context
OrdersScreen today owns the board subscription, setup status, AppState refresh, notification-permission request and the
"new order brings New tab to front" effect. Move those into MainShell (same calls, same events) and pass data down as
props (PLAN Contracts `OrdersScreen` props). Until T05, OrdersScreen keeps its current body but takes props.
History/Insights/Account tabs and pages render a placeholder `EmptyState` until T06–T08.

## Steps
1. `backAction({tab, stack})`: stack non-empty → pop; else tab ≠ 'orders' → {tab:'orders', stack:[]}; else null.
   BackHandler 'hardwareBackPress' returns true when backAction is non-null.
2. MainShell state: tab, stack, segment (OrderPhase, default 'PENDING'), board (getBoard + onBoardChanged), setup
   (getSetupStatus; refreshed with board on AppState 'active' + pollNow), store = useStoreStatus(shopId),
   profile = useShopProfile(shopId, board). Pending count increase → tab 'orders', stack [], segment 'PENDING'.
   Request POST_NOTIFICATIONS on mount (Android ≥ 33) exactly as today.
3. Tabs mount lazily on first visit, then stay mounted (hidden with display 'none') to keep their state.
4. TabBar: white, hairline top, 4 items (icon + caption): Orders receipt-text, History history, Insights chart-column,
   Account store; active = blue, inactive = ink3; Orders shows a red count bubble when pending > 0; each item ≥ 56 dp
   tall, role 'tab', accessibilityLabel e.g. "Orders, 2 new".
5. App.tsx: StatusBar dark-content on colors.bg; SafeAreaView edges top/left/right (TabBar handles bottom inset);
   session ? <MainShell session/> : <LoginScreen onLoggedIn/>; keep onSessionEnded behavior.
6. LoginScreen (same state, validation messages, requestOtp/login/startSession/onLoggedIn calls): white screen; blue
   rounded-square app mark with store icon; largeTitle "Log in to your store"; body "We'll send a 4-digit code to
   your mobile."; phone field with fixed "+91" prefix, 56 dp; primary l Button "Send OTP"; OTP step: 4 boxes driven by
   one hidden TextInput (tap boxes focuses it), "Verify & start", resend countdown text button, "Change number" ghost.
7. App.test.tsx: add a global fetch mock that rejects (offline) in beforeEach so no test reaches the network; keep both
   existing tests and their expectations unchanged.

## Test cases
- TC1 backAction({tab:'history',stack:['timings']}) → {tab:'history',stack:[]}; ({tab:'history',stack:[]}) → {tab:'orders',stack:[]};
  ({tab:'orders',stack:[]}) → null.
- TC2 existing App tests: login shows 'Send OTP'; session shows 'Shop #' and 'No new orders'.
- TC3 shell: board with 1 PENDING → tab bar text contains 'Orders' and badge '1'.
- TC4 shell: start on History (press tab), then emit qvBoardChanged with a PENDING order → Orders content visible ('New').
- TC5 login: entering '12345' and pressing Send OTP shows 'Enter a valid 10-digit mobile number' and does not call fetch.
